## 1. 要解决的体感

现在是纯请求–响应：角色没有「生活痕迹」——不问时间、不提地点、不记得自己刚做过什么。用户离开再回来，对话像永远停在上一句。

更有真人感的最小三刀：

1. **W-01**：每轮注入一行「此刻」上下文（本地时间 + 粗略地点/场景标签），角色开口会带时间感。
2. **W-02**：角色有可求值的 `presence`（在哪 / 在途 / 刚离开），惰性计算，不靠全日闹钟。
3. **W-03**：偶发生活事件落流水，后续对话可被召回——不是作息表，没有到点必须做的事。

---

## 2. 正当性边界

**必须写死（防止后续会话把产品重定位）：**

> 只挪「让对话有生活痕迹」这一层：角色会提到自己此刻在哪、刚做了什么、等了多久。
> 不挪「它真的有独立人格和时间表」那一层：没有全日作息表、没有到点必须做的事、不由它自己决定要不要找你。

主动找你仍走既有 C-05 urge / 过线规则（《主动互动设计备忘》）。本备忘只给对话与采样**增加世界状态输入**，不另开「角色自己排日程」产品线。

## 3. 三个借用来的手法

### W-01 此刻上下文注入（P1）

- 在统一注入出口（见记忆合同第 5 条）装配一行短上下文：本地日期时间、可选场景/地点标签。
- 不读长历史、不另打模型；失败则静默跳过该行。
- **阻断**：须先有 token 预算（D-25），否则硬截会挤掉记忆/honor。

### W-02 `presence` 惰性求值（P1，依赖 W-01）

- 表或字段保存：当前节点、状态（idle / traveling / busy 等）、`since`、可选 `eta`。
- **谁问谁算**：`resolvePresence(now)`；未到 ETA 不改变结果。
- 不引入独立 Life Runtime；不在每分钟用 LLM「演一天」。

### W-03 `life_events` 流水（P2，依赖 W-02）

- 在主动 tick 的**世界状态推进**分支：纯计算或落一条流水（地点变化、小事件文案）。
- **硬约束（与主动备忘一致）：状态推进分支不得调用 LLM。**
- 事件可被后续注入/召回；不是「到点必做」任务队列。

W-01～W-03 做完即可验收最小闭环；**W-04** 属打磨（跨重启流逝补偿），不进最小闭环。

## 4. 明确不做（本备忘范围）

- **W-05**：地图编辑器 / 全日作息引擎（Pulse / Yuralume / nyairo 最重块）——**明确不做**。≠ W-03 生活痕迹。
- 角色自己排日程再决定找你（仍归主动备忘 W-05 边界）。
- 独立 Life Runtime 进程、事件总线、分段审计账本。
- 为世界感换 Python / 插件栈 / `vendor/hermes`。

## 5. 表结构与惰性求值（草案）

### `presence`（每角色一行或等价）

| 字段 | 含义 |
| ---- | ---- |
| `character_id` | 角色 |
| `place_id` / `place_label` | 粗粒度地点或标签 |
| `status` | `idle` / `traveling` / `busy` / … |
| `since` | 进入该状态的 UTC 时间（单一格式，见 D-26） |
| `eta` | 可选；未到不改结果 |
| `updated_at` | 上次写入 |

求值：`resolvePresence(characterId, now)` → 供注入与 W-03 决策输入；**不**在求值路径打 LLM。

### `life_events`（流水）

| 字段 | 含义 |
| ---- | ---- |
| `id` | 主键 |
| `character_id` | 角色 |
| `kind` | 事件类型短码 |
| `summary` | 可注入的短文案 |
| `place_label` | 可选 |
| `created_at` | UTC 单一格式（D-26） |
| `recallable` | 是否允许进注入池 |

惰性：列表按需取最近 N 条；与记忆共用注入层，受 token 预算裁剪。

## 6. 三个前置工程债（开工阻断）

| 债 | 现状 | 阻断 | 处级 |
| -- | ---- | ---- | ---- |
| **D-25** 无 token 预算 / 注入硬截 | 主聊天 `LIMIT 40` 等硬编码；全仓库零 token 估算 | 时间/地点/状态注入挤占预算且无溢出保护 → **阻断 W-01** | 高。先补按 token 裁剪的注入器，封在注入函数内（记忆合同第 3/5 条） |
| **D-26** `created_at` 双格式 + **存量归一化迁移** | DEFAULT `datetime('now')` vs JS `toISOString()` | 流逝/ETA 解析歧义 → **阻断 W-02/W-03** | 高。统一单一 UTC 格式；**含存量**：仿 `moments__m06`（建临时表 → 回填 → DROP 旧表 → RENAME）归一历史行，不能只写「统一格式」 |
| **D-15** 内存定时器重启即丢（既有债，**不新造编号**） | `pendingTimers` 等内存 Map | W-03/W-04 跨重启依赖 → **补注：W-03/W-04 跨重启依赖此债先收** | 建议阶段仍 ARCH-3 |

## 6.5 与记忆 / 压缩的边界（2026-10-16）

| 层 | 内容 | 现网实现 | 碰不碰 LLM 上下文 |
| -- | ---- | -------- | ----------------- |
| **L1 近窗** | 私聊最近 N 条消息 | `LIMIT ?` = `historyMessageCap()`（默认 40，`PROMPT_HISTORY_MESSAGE_CAP`）+ D-25 `takeRecentWithinTokenBudget`（默认 3072 token）装配 | 是（对话历史） |
| **L2 记忆行** | `memories` 结构化行 + `supersede` | 候选 ≤40（`MAX_ACTIVE`）→ D-25 注入预算（默认 512 token）装配 → 注入 ≤8 条（`INJECT_MAX`） | 是（经统一注入出口） |
| **L3 世界状态** | W-02 `presence` 惰性求值 + W-03 `life_events` 流水 | 纯计算 / 落表；W-01 此刻行为 pinned 注入项（不裁剪） | 状态推进不碰；只以短行经注入出口进入 |

**结论：W 系列不依赖长记忆和压缩；注入统一出口（记忆合同第 5 条）是唯一扩展插槽。**

## 7. 参考：nyairo 评估结论

触发：评估外部项目 [nyairo](https://github.com/L1AN929/nyairo)（Apache-2.0，v0.2.0-rc3），2026-10-15。

| 可吸收（原则） | 不要照搬（会偏航） |
| -------------- | ------------------ |
| 位置是状态 + 时间戳 + ETA，未到不改变结果 | 38KB 的 `world_body_service.py` 与 26KB 测试 |
| 自主产生的事件落流水表，可被后续召回 | 独立 Life Runtime 进程 + 事件队列 + 分段审计 |
| 记忆纠正后要清除已复述旧事实的再注入 | M0/M1/M2/M37 四层记忆分层与 MemoryControlLedger |
| 删除 = 停召回但保留原始证据（我们已有 supersede） | Python + 插件体系 + `vendor/hermes` 内置运行时 |

**结论：语言与栈不变。** 继续 Vite + Vue3 + Fastify + SQLite；nyairo 是 Python 单体重框架，代码一行都搬不了，能搬的是设计手法。当参考，不当基线；不因此换栈。
