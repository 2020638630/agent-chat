# Agent Chat · 主动互动设计备忘

产品是多角色社交客户端，不是跑团酒馆。下文若写「酒馆礼貌」，仅指产品侧写死的唤起规则。

- 日期：2026-09-16
- 状态：2026-09-17 开 C-05 第一刀（仅私聊）。M-07 仍不开发。
- 挂钩问题：C-05（会话主动）、M-07（动态反应）、C-03（未读依赖主动才能造真实未读）、M-02（关系图谱，更晚）
- 问题表：`AgentChat-问题记录.xlsx`

---

## 1. 要解决的体感

现在是纯请求–响应：用户不发，角色不说话。更有真人感的两条：

1. 用户离开某场会话后，角色有时会先开口（写入已有私聊/群，不是新频道）。
2. 用户自己发了空间动态后，已导入角色有时会赞或评一句。

不做：Discord 在线状态、语音房、角色互评刷屏、整日作息模拟（Pulse / Yuralume 那一档）。

---

## 2. 架构分层（核心不是闹钟）

定时器只是采样，不是决策。

```
事件改写冲动（urge）
    ↑ 你回复 / 你消失 / 你发动态 / 他刚主动过
全局慢采样（约每分钟醒一次，多数角色本拍跳过）
    → 有没有人过线？没有则结束（不读长历史、不打模型）
    → 过线者里全场只留 1 人
    → 再读该角色近期对话或那条动态
    → 决定动作：私聊一句 | 点赞 | 短评 | 仍然沉默
```

- 实现上：Fastify 进程内调度即可，不必独立 OS 线程 / 独立服务。
- 后端没开则不会主动——单机产品的诚实限制。
- 模型走现有 chat 通道（Ollama 或 DeepSeek 等云端）。能力不按「只有 9b」封顶；本机档更保守（更高冷却、更容易沉默），云端档判定可以更准。禁止为「选不选说话」再开一套供应商。

---

## 3. 性格阈值（可变）

人设的一部分。预设几档，导入或角色资料可改，不要做成开放标签云。

建议起步档：

| 档 | 直觉 | 阈值 / 涨速 | 过线后更倾向 |
|---|---|---|---|
| 克制 | 夜见 | 高、涨得慢 | 少开口；空间往往只赞 |
| 平和 | 林深 | 中 | 短讯或一赞 |
| 外向 | 小春 | 低、见动态更易动 | 短评或找人说话 |

可再暴露三个数（进阶，不必导入时全摊开）：阈值、冷落涨速、过线后偏「说话」还是「动空间」。

情绪 / 冲动是 **快变量**，由事件改写，采样器只读，不在每分钟现场用 LLM「算一遍情绪」。

---

## 4. 唤起规则（写死）

酒馆礼貌，不做规则引擎，不按角色自定义。

- 每拍全场最多一个角色出手
- 刚主动过 → 冷却
- 用户连续不回 → 停止再追
- 勿扰时段不发起私聊（赞评可另议）
- 未过阈值：不读大段历史、不调用模型
- 空间动作只反应 **用户自己的动态**，不做角色互评（仍 M-02）
- 总开关关闭时，采样空转也不许发
- 群聊若做：一群一条流里整群只抽一人，或第一刀只做私聊

全局旋钮只留政策，不留脚本：总开关（默认关）、安静时段、每天全场最多几下。

---

## 5. 好感度 vs 阈值 vs 图谱

不要并成一个数。

| 层 | 含义 | 速度 | 归属 |
|---|---|---|---|
| 冲动 / 阈值 | 这一分钟想不想动手 | 快 | 主动互动 |
| 好感度 | 熟不熟、软不软 | 慢 | 单独关系字段（你 ↔ 该角色） |
| 关系图谱 | 谁认识谁、可见性、互评 | 更慢 | M-02，晚做 |

好感度 **调制** 阈值，不等于阈值：

- 高好感不应变成更爱刷屏；熟了更应懂分寸（不回更早闭嘴）
- 低好感不应永远零主动，否则冷淡开局无法试探
- 低好感过线 → 更倾向赞；高好感才提昨天的事（开环）

现在产品是星形（用户对每个已导入角色），没有图谱好感也能工作。

## 6. 两条出口怎么挂问题表

- **C-05**：采样过线 → 往已有会话写入一条助手消息 → C-03 未读第一次有真实来源。与 M-03「角色自己定时发动态」分开。
- **M-07**：用户 insert 动态为事件 → 延迟一小段 → 抽 0～1 人评、0～2 人赞（赞可不走 LLM）。等 M-06 验收后再开。不并入 M-06。

建议以后的第一刀仍只选一条出口验收，不要心跳和空间反应同一包。

---

## 7. 明确不做（本备忘范围）

- 角色全日作息 / 自己过日子再决定找你
- 每角色独立 cron 与可编辑触发器列表
- 浏览器里做定时（切标签会被节流；调度在 8787）
- 为重构而引入网关、MCP、独立 worker
- 密钥入库；git push 纪律不变

---

## 8. 参考（评估用过，不引入依赖）

- SillyTavern Unprompted / Idle：闲置试探 + `[saynothing]`
- EchoText Proactive：浏览器定时不可靠，要服务端调度
- 溪语 / Pulse / Yuralume：冲动或三闸 + 日限额 + 默认沉默
- AIRI Heartbeat 讨论：多数心跳零动作

## 9. 对照：豆包《四层记忆 + 主动消息》v2（2026-09-17）

文件：`artifacts/Agent记忆与主动对话设计方案.html`。评估结论：**当参考，不当基线；不因此换栈、不因此拆包。**

那份方案写的是「助理 / 提醒 / 长期记忆 CRM」，不是多角色社交。任务到期推送、pgvector、记忆管理页、WebSocket / 厂商推送、Temporal / Celery，都是另一类产品。

| 可吸收（原则） | 不要照搬（会偏航） |
|---|---|
| 模型不管钟点与调度 | 用到期任务当主动主路径（闹钟化，与 §2 冲突） |
| 先策略门再说话；默认可关 | PostgreSQL + pgvector / 独立向量库 |
| 弱隐含跟进默认不建任务 | 在线状态、离线推送、保活关怀 |
| 记忆以后要能改、能替代，不要纯追加文本 | L0–L3 + embedding 作为 C-05 前置 |
| 在线回复与事后分析拆开，不拖慢气泡 | 每角色 cron、独立 worker、新语言 |

语言与栈：继续 Vite + Vue3 + Fastify + SQLite。单机、全场每拍至多一人，调度不是瓶颈。不为记忆 / 主动引入 Python、Go、Rust、Celery、Temporal。真要 embedding，用现有 Node 调 HTTP，不换运行时。

C-05 / M-07 仍按本文 §2–§6，默认不开发。
