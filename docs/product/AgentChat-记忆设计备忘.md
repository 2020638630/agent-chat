产品是多角色社交，星形：你 ↔ 每个角色一份私档。不是助理 CRM，不是提醒任务。

## 合同（升级靠这个，不靠换栈）

1. 记忆是行，不是 prompt 散文。一条一事，冲突 `supersede`。
2. 聊路径与写路径分开：气泡先回；提炼 `after_turn` 异步，失败不影响已发出的回复。
3. 注入是「按角色取 N 条」；底层今天 SQLite，以后可换 FTS / embedding，调用方不变。
4. urge / 好感 / 私档 / 图谱分表。C-05 采样器不因本包改逻辑。

栈：现有 SQLite。不上 Postgres、向量库、新语言、独立 worker。

## 第一刀范围（R-02）

- 仅私聊。群聊不写共享记忆。
- 无管理页也可以，先有 `GET` 便于验收；角色主页列几条可选。
- 不做用户编辑页、不过期策略的复杂 UI、不做 embedding 列（可以后加空列，本包不必）。
